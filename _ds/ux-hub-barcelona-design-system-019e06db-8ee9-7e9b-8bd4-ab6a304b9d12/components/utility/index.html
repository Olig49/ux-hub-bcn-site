If your OS/browser is set to reduce motion, this track is static — that's mobile-tweaks.css:15 working correctly, not a bug in this catalog page.

BackToTop — .to-top

Fixed pill, bottom-right, appears after 600px of scroll. Source: UX Hub Barcelona.html:534-536 (markup) + :616-622 (scroll + click behaviour). Forced visible here (.show class added) since it's normally hidden until scrolled.

Bottom-right is a deliberate choice — the spec notes the bottom-left corner is reserved for the third-party cookie-consent widget (GetTerms CMP, loaded in both pages' `<head>`), so BackToTop and the cookie widget never fight for the same corner. At ≤600px it shrinks from 48px to 44px (site.css:492) — still meeting --uxh-tap-min. Smooth-scroll is only used when motion is welcome: sponsors.html's handler explicitly checks prefers-reduced-motion: reduce and falls back to an instant jump (sponsors.html:348-349); the homepage's handler always passes behavior: 'smooth' without that check (UX Hub Barcelona.html:621) — a real, small inconsistency between the two pages worth reconciling in favour of the sponsors.html version.

Reveal-on-scroll — .reveal

Opt-in fade+rise-in, applied to almost every top-level section block across both pages. Source (behaviour): UX Hub Barcelona.html:624-641 and sponsors.html:339-344; CSS: site.css:494-498.
