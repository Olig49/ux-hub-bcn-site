This used to be a single email field + inline "Sign up" button in a pill row — an earlier version of this catalog page still showed that markup after the real form was rebuilt to match Brevo's actual required fields (EMAIL, FIRSTNAME, LASTNAME, LINKEDIN, JOB_TITLE, plus GDPR consent), so the preview no longer matched what index.html actually ships. Fixed to mirror the real five-field form exactly (ids prefixed ds- here only to avoid colliding with the real page's ids, since this file loads the same site.css). The real form posts to Brevo (`sibforms.com`) — the action URL above is redacted to a placeholder in this catalog so the button can't submit real signups from a documentation page; every class and layout attribute is otherwise verbatim. The role="status" acknowledgement (.mail-ack) is normally hidden until the inline submit handler reveals it (index.html:700) — shown here in its default hidden state. See `forms/README.md` for full field-by-field documentation, including why `novalidate` + custom JS validation replaced the browser's native validation bubble.

DonateFacts — .donate-facts

The €-amount / impact list in .donate-copy, to the left of DonateForm on the same dark panel — not part of the card or form itself.

  • €15snacks for 4 tables of newcomers
  • €25materials for three events
  • €45drinks for a third of the room at one meetup

Rows use a fixed-width grid column (44px 1fr) with align-items: start, not a flex row with align-items: baseline — baseline alignment pinned each amount to the first line of its description, which left it stranded near the top on a two-line row like the first and third here, with nothing next to the wrapped second line. Top-aligning against a fixed column fixes both the vertical alignment and guarantees every description starts at the same x, regardless of how many digits the amount has.

DonateForm — .donate-card

Warm-white card on the dark Donate panel. Source: index.html:422-438, shown here on its native dark surface.

Choose an amount

Any amount is a one-time donation only.

You’ll be taken to Stripe for secure one-off or recurring payment.

Amount chips and frequency pills are populated/kept in sync by inline JS in index.html, which maps the selection to one of six pre-built Stripe Payment Links (three amounts × two frequencies) or, for "Any amount", opens Stripe's own customer-enters-amount page directly. There used to be a fifth option here — a free-text "custom amount" input — but it asked visitors to type an amount twice (once on this page, once again on Stripe's, since Payment Links can't accept a pre-filled custom price via URL) so it was replaced by this selector instead. "Any amount" also isn't a fourth chip in the `.amounts` row — an earlier version was, and its longer label got squeezed into a ~76px cell with no horizontal padding, so it moved to its own full-width row inside the same `.amount-group` radiogroup. Because that Stripe link is one-time only, selecting it also disables the Monthly toggle below and shows the note under the frequency pills. Hover the info icon (or focus it) to see the fine-print tooltip driven by data-tip + ::after.
